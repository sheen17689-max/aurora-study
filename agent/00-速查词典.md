## 一、核心范式与架构模式

### `Workflow` vs `Autonomous Agent`
- **类别**：`系统架构模式`
- **核心区别**：
  - **Workflow（工作流）**：系统的主执行流程由**硬编码的程序逻辑（Python 代码/状态机）**控制，LLM 仅在特定节点作为高效的处理步骤（如总结、分类、结构化提取）。确定性高、延迟可控、容易调试。
  - **Autonomous Agent（自主智能体）**：系统的下一步行动由 **LLM 动态自主决定**。大模型根据环境 Observation（观察），自主判断是否继续调用工具、调用哪一个工具，直到模型自发判定任务完成。适应性极高但具备随机性与循环风险。
- **代码示例**：
```python
# 1. Workflow 模式: 代码决定拓扑流向
def workflow_pipeline(user_query):
    draft = llm.generate(f"写初稿: {user_query}")
    feedback = evaluator_llm.generate(f"评估并找茬: {draft}")
    final_output = llm.generate(f"根据批评修改: {draft}\n意见: {feedback}")
    return final_output

# 2. Agent 模式: 模型自己决定下一步走哪
messages = [{"role": "user", "content": user_query}]
while True:
    response = llm.generate(messages, tools=available_tools)
    if not response.tool_calls:
        return response.content  # 模型决定完结
    # 模型决定调用工具并继续循环
    obs = execute_tool(response.tool_calls[0])
    messages.append({"role": "tool", "content": obs})
```

### `ReAct` vs `Plan-and-Solve`
- **类别**：`推理与规划范式`
- **核心区别**：
  - **ReAct（Reasoning + Acting）**：**单步交替循环**。一步思考（Thought）→ 一步行动（Action）→ 一步环境反馈（Observation）→ 再进一步思考。长处是动态应变能力强，遇到工具报错能立刻修正。
  - **Plan-and-Solve（计划与求解）**：**两阶段宏观分解**。第一阶段由 Planner 先生成一份完整的分解子任务清单（Sub-tasks 1, 2, 3...）；第二阶段由 Executor 顺次或并发执行每一个子任务。长处是全局视野好、Token 消耗集中，但在中间步骤出现外部环境突发状况时应变较慢。
- **代码示例**：
```python
# Plan-and-Solve 两阶段伪代码
plan = planner_llm.chat("将'帮我调研 3 家上海 AI 咖啡馆并生成对比表格'拆解为子任务步骤")
# plan = ["1. 检索上海 AI 咖啡馆", "2. 提取名称、地址、特色", "3. 组织 Markdown 表格"]
results = []
for subtask in plan:
    step_res = executor_agent.run(subtask)
    results.append(step_res)
final_report = aggregator_llm.chat(f"根据以下执行结果汇总: {results}")
```

## 二、工具与环境协议

### `Function Calling` vs `MCP (Model Context Protocol)`
- **类别**：`工具与上下文协议`
- **核心区别**：
  - **Function Calling**：厂商 API 级能力（如 OpenAI / Anthropic）。开发者在 API 请求里以 JSON Schema 提供工具定义，大模型输出 `tool_calls` JSON 字段，但**执行环境与工具实现全由开发者自行编写胶水代码**。
  - **MCP（Model Context Protocol）**：开放标准化客户端-服务端架构协议。工具的提供者（Server）与工具的使用者（Client / Host）完全解耦。一个 MCP Server（如 SQLite、Git、GitHub、文件系统）只需实现一次标准协议，任何支持 MCP 的宿主（Claude Desktop、Cursor、IDE、自建 Agent）均可即插即用，无需重复写封装胶水层。
- **代码示例**：
```json
// Function Calling: 开发者在单次 HTTP 请求里手写 tools 描述
{
  "name": "get_weather",
  "description": "获取指定城市的天气",
  "parameters": {
    "type": "object",
    "properties": {
      "city": { "type": "string" }
    },
    "required": ["city"]
  }
}
```

### `Zero-shot CoT` vs `Few-shot CoT`
- **类别**：`提示与推理技术`
- **核心区别**：
  - **Zero-shot CoT**：零样本思维链。不需要给任何示范样例，只需在 Prompt 结尾加上神奇咒语 **「Let's think step by step」（让我们一步步思考）**，即可激发 LLM 激活潜在推理步骤。
  - **Few-shot CoT**：少样本思维链。在 Prompt 中显式提供 2~3 个完整的“问题 - 详细推理推导步骤 - 最终答案”示例，模型将严格模仿示例中的推理格式与分解逻辑。

## 三、记忆系统与 RAG

### `Working Memory` vs `Episodic Memory`
- **类别**：`Agent 记忆分层`
- **核心区别**：
  - **Working Memory（工作记忆 / 短期记忆）**：直接装载在 LLM 当前上下文窗口（Context Window）里的内容。包含最近几轮对话历史、系统 Prompt、当前正在执行的工具结果。断电/会话结束即丢失，受 Token 长度限制。
  - **Episodic Memory（情景记忆 / 长期记忆）**：持久化保存在外置存储（如 SQLite、向量数据库、文件系统）中的历史经历。当遇到相似场景时，通过 Embedding 相似度检索或时间戳检索重新激活装入 Working Memory。
