# 提示工程与结构化输出（Prompt Engineering & Structured Outputs）

> 掌握度：🟡 接触过

## 一句话直觉
提示工程与结构化输出就像给大模型戴上**“工业级安全模具”**：大模型天性散漫、喜欢自由发挥文本；但下游的 Python 代码需要严丝合缝的 JSON 字典。通过结构化输出，我们可以强行让大模型只在限定的模具里灌胶成型，确保下游程序绝对不会因为字段拼写错误而崩溃。

---

## 📌 结构化输出演进史

```
阶段 1: 弱提示约束 (Prompting)
"请仅以 JSON 格式输出，不要包含任何 markdown 标记" ──> 仍然有 10% 概率吐出闲聊或未转义引号

阶段 2: 正则/Grammar 采样 (Jsonformer / Outlines)
在模型 Decode 阶段修改 Logits，非 JSON 合法字符的生成概率强制归零 ──> 100% 格式合法，但需要私有部署

阶段 3: 厂商原生 Strict Mode (OpenAI / Anthropic Structured Outputs)
传入 Pydantic / JSON Schema，模型底层 Constrained Decoding ──> 100% 契约遵从，生产首选
```

---

## 💻 Pydantic 原生绑定结构化输出

```python
from pydantic import BaseModel, Field
from typing import List, Literal

class AgentAction(BaseModel):
    thought: str = Field(description="详细分析当前观察并推理下一步")
    action_type: Literal["call_tool", "finish", "ask_user"] = Field(description="行动类型")
    tool_name: str = Field(default="", description="调用的工具名称")
    parameters: dict = Field(default_factory=dict, description="工具所需的结构化入参")
```
