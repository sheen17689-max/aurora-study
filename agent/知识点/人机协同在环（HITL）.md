# 人机协同在环（Human-in-the-Loop, HITL）

> 掌握度：🟡 接触过

## 一句话直觉
人机协同在环就是给 Agent 装上**“核导弹发射的物理双人钥匙”**：日常巡航、侦查计算都可以全自动进行；但在涉及转账付款、删除数据库、向全员发邮件等高危破坏性操作前，系统必须停下来等待人类指挥官亲手点击「确认执行」，确保绝对安全可控。

---

## 📌 状态图断点恢复机制（LangGraph 范式）

```
[Agent 思考] ──> [准备调用支付 API] ──> 🛑 触发 Interrupt (保存 Checkpoint)
                                              │
                                              ▼
                                   [向人类推送审批卡片]
                                              │
                         ┌── 拒绝 ────────────┴──────────── 批准 ──┐
                         ▼                                         ▼
                 [中止并反馈原因]                           [恢复状态机并执行 API]
```

## 思考与自测
- 在设计完全自主 Agent 时，为什么绝对不能省略人机在环（HITL）审批机制？
- LangGraph 是如何利用状态持久化（Checkpointer）实现即使服务器重启也不会丢失审批断点的？
- 除了高危工具审批，人类在环还能在哪些场景下（如提供额外提示、修改前序错误状态）对 Agent 进行干预？\n
