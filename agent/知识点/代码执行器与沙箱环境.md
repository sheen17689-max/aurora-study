# 代码执行器与沙箱环境（Code Interpreter & Sandboxing）

> 掌握度：🟡 接触过

## 一句话直觉
代码执行器就像给大模型配备了一台**“隔离在防爆玻璃后的超级计算机”**：面对复杂的科学计算、数据分析或画图需求，不要让大模型在脑子里心算（极易算错），而是让它写一段 Python 脚本丢进防爆箱执行，直接抓取运行结果，既精准无误，又不会威胁到宿主服务器的安全。

---

## 📌 沙箱安全与执行协议

```
┌──────────────┐                  ┌─────────────────────────────────┐
│ 大模型       │ ── 生成代码 ───> │ 安全沙箱容器 (Docker / E2B / gVisor)│
│ (Brain)      │ <── 执行结果 ─── │ • 禁用危险系统调用 (fork, root) │
└──────────────┘ (Stdout/Images)  │ • 内存/CPU/执行时长严格熔断      │
                                  │ • 网络外联白名单控制            │
                                  └─────────────────────────────────┘
```

## 思考与自测
- 为什么纯靠大模型的自然语言推理进行复杂浮点数运算极易出错，而代码解释器能做到 100% 准确？
- 允许大模型自主生成并执行 Python 代码，存在哪些致命的安全注入风险？如何利用 Docker/eBPF 进行沙箱隔离？
- 代码执行超时（如死循环 `while True`）时，宿主程序应当如何实现优雅熔断？\n
