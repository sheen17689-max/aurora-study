# 张量维度与广播机制（Tensor Dimensions & Broadcasting）

> 掌握度：🟡 接触过 ｜ 所属模块：数学与数据地基

## 一句话直觉
张量是深度学习的**“通用数据容器”**（0D标量、1D向量、2D矩阵、3D序列、4D图像）；而广播机制（Broadcasting）就像**“虚拟复印机”**：当两个形状不同的张量进行数学运算时，在不占用额外显存的前提下，自动将较小维度的张量在逻辑上拉伸对齐，使得逐元素计算能够顺畅执行。

---

## 核心要点与数学公式

### 1. 深度学习常见张量维度（Tensor Shapes）

| 维度（阶数） | 经典形状 (Shape) | 典型应用场景 |
| :--- | :--- | :--- |
| **0D (标量)** | `()` | 损失值 `Loss = 0.42`、学习率、指标得分 |
| **1D (向量)** | `[Features]` 如 `[128]` | 偏置向量 $b$、单一样本特征、词汇表嵌入索引 |
| **2D (矩阵)** | `[Batch, Features]` 如 `[32, 512]` | 全连接层输入输出、权重矩阵 $W$、表格数据 |
| **3D (时序/文本)** | `[Batch, Seq_Len, Hidden_Dim]` 如 `[16, 50, 768]` | Transformer 文本嵌入、RNN 时间序列数据 |
| **4D (视觉图像)** | `[Batch, Channel, Height, Width]` 如 `[8, 3, 224, 224]` | CNN 图像输入、特征图（Feature Maps） |

---

### 2. 广播机制（Broadcasting）严格两大法则

当两个张量 $A$ 和 $B$ 进行二元逐元素运算（`+`、`-`、`*`、`/`）时，系统会**从最后面（最右侧）的维度开始向前逐个对比**：

1. **维度兼容性条件**（满足其一即可）：
   - 两个维度大小**严格相等**；
   - 其中一个维度的大小**必须为 1**（或该维度在其中一个张量中不存在）。
2. **逻辑拉伸规则**：
   - 维度大小为 1 的轴会被自动“复制/拉伸”至与对方相同的尺寸；
   - 缺少前置维度的张量会在最左侧自动补 1。

#### 实例解析：
- `[32, 64, 128]` 与 `[128]` $\implies$ `[128]` 补齐为 `[1, 1, 128]` $\implies$ 成功广播为 `[32, 64, 128]`
- `[8, 3, 224, 224]` 与 `[1, 3, 1, 1]` $\implies$ 成功广播为 `[8, 3, 224, 224]`（常用于图像通道级归一化）
- `[32, 64]` 与 `[32]` $\implies$ ❌ **无法广播报错**！因为最右侧维度 $64 \neq 32$ 且均不为 1（必须显式使用 `unsqueeze(1)` 转为 `[32, 1]`）。

## 最小验证代码（NumPy & PyTorch 广播实战）

```python
import numpy as np
import torch

# 1. 模拟 4 张 RGB 图片特征图: [Batch=4, Channel=3, H=2, W=2]
images = torch.randn(4, 3, 2, 2)

# 2. 通道均值向量 (每个通道减去一个固定均值): [Channel=3]
mean = torch.tensor([0.485, 0.456, 0.406]).view(1, 3, 1, 1) # 显式对齐为 4D

# 3. 触发自动广播运算
normalized_images = images - mean
print("广播后形状:", normalized_images.shape) # 输出: torch.Size([4, 3, 2, 2])

# 4. 2D 与 1D 矩阵加偏置
W_out = torch.randn(32, 10)  # [32 个样本, 10 维输出]
b = torch.randn(10)          # [10 维偏置]
out = W_out + b              # b 自动广播为 [32, 10]
print("全连接加偏置形状:", out.shape)
```

## 工程与业务映射

- **PyTorch 常用维度变换算子**：
  - `unsqueeze(dim)` / `squeeze(dim)`：插入或剔除大小为 1 的轴；
  - `view()` / `reshape()`：在总元素数不变的前提下重塑维度；
  - `permute(dims)` / `transpose(dim0, dim1)`：交换轴顺序（如将 PyTorch 的 `[B, C, H, W]` 转为 OpenCV/Numpy 的 `[B, H, W, C]`）。
- **嵌入式 / RKNN 部署避坑**：
  - RKNN / NPU 硬件对 `NCHW` 格式通常具有极高的流水线加速，若网络中频繁出现 `Reshape`、`Transpose` 或不规范的广播，会导致在 NPU 内部插入大量 CPU Fallback 内存搬移，显著拖慢推理帧率。

## 思考与自测

- **自测 1**：张量 $A$ 形状为 `[256, 1]`，张量 $B$ 形状为 `[1, 512]`，它们能直接相加吗？相加后的结果形状是什么？
  > *解析*：可以。根据广播规则，$A$ 在第 1 维拉伸为 512，$B$ 在第 0 维拉伸为 256，相加后结果形状为 `[256, 512]`（这是生成网格坐标与外积计算的高频技巧）。

- **自测 2**：在图像预处理中，为什么要将 PIL/OpenCV 读取的 `(H, W, C)` 形状转换为 `(C, H, W)`？
  > *解析*：PyTorch 和主流 GPU 卷积算子（如 cuDNN）在底层基于 `NCHW` 内存布局进行了极致的并行访存优化（同一通道像素在内存中连续排布，便于多通道卷积核批量提取）。
