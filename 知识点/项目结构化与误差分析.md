# 项目结构化与误差分析（ML Project Structuring & Error Analysis）

> 掌握度：🟡 接触过 ｜ 所属模块：工程实践

## 一句话直觉
误差分析是算法工程师的**“疑难杂症会诊指南”**：当模型在测试集上表现不佳时，初学者往往会无头苍蝇式地盲目更换模型架构或调大网络；而资深工程师会**肉眼抽检抽查 100 个错误样本（Error Analysis）**，统计各类错误归因（如模糊失焦占 60%、遮挡占 30%、标签打错占 10%），用最小的工程代价精准定位最大的性能瓶颈。

---

## 核心要点与数学公式

### 1. 经典吴恩达误差分析表格法（Error Analysis Table）

在验证集上拉出 100 个模型预测错误的样本，人工肉眼逐条审查并打勾分类：

| 样本编号 | 预测错误现象 | 图像严重模糊/暗光 | 严重遮挡重叠 | 真实标签标注错误 | 罕见冷门类别 | 备注 / 应对方案 |
| :--- | :--- | :---: | :---: | :---: | :---: | :--- |
| #01 | 预测为背景 | ✅ | | | | 增加暗光数据增强 |
| #02 | 误将狗识别为猫 | | ✅ | | | 引入 CutMix / 遮挡增强 |
| #03 | 标注为车但框歪了 | | | ✅ | | 清洗清洗标注数据 |
| **总计占比** | **100%** | **55%** | **25%** | **12%** | **8%** | **结论：优先解决暗光模糊问题！** |

---

### 2. 偏差与方差的诊断罗盘（Bias-Variance Diagnostics）

```
【人类基准误差 (Human Level)】: 1%
   │
   ▼ ──▶ 【可避免偏差 (Avoidable Bias)】= 训练集误差 (5%) - 人类基准 (1%) = 4% (欠拟合)
【训练集误差 (Training Error)】: 5%
   │
   ▼ ──▶ 【方差 (Variance)】= 验证集误差 (10%) - 训练集误差 (5%) = 5% (过拟合)
【验证集误差 (Validation Error)】: 10%
```

- **若“可避免偏差”高（欠拟合）**：加大网络深度/宽度、增加训练轮次、更换更强大 Backbone；
- **若“方差”高（过拟合）**：增加训练数据量、加大正则化（Dropout / Weight Decay）、数据增强。

## 思考与自测

- **自测 1**：如果误差分析发现测试集有 2% 的样本存在人工标注错误（Label Noise），是否需要立即花大代价把全量数据的标签全部人工重标一遍？
  > *解析*：不需要。如果当前模型的总测试误差还有 15%（其中主要矛盾是 10% 的严重模糊导致），解决模糊问题性价比远高于修正 2% 的标注噪声；只有当模型总误差已经逼近 3% 时，这 2% 的标注噪声才会成为限制模型天花板的主导因素。
