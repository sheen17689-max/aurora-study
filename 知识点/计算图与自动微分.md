# 计算图与自动微分（Computational Graph & Autograd）

> 掌握度：🟡 接触过 ｜ 所属模块：神经网络基础

## 一句话直觉
如果深度学习是一个复杂的数学复合函数，计算图就是**它的“流水线生产记录与逆向账本”**：前向传播时像录像机一样记录每一个变量经历了什么运算（加法、乘法、激活），反向传播时顺着这个有向无环图（DAG）像倒带一样调用每个算子的局部导数，自动完成全网链式法则求导。

---

## 核心要点与数学公式

### 1. 动态计算图（Dynamic Computational Graph / DAG）
考虑一个简单的计算过程：$L = (w \cdot x + b - y)^2$
```
 x ──┐
     ▼ (×) ──▶ z1 ──┐
 w ──┘              ▼ (+) ──▶ z2 ──┐
               b ──┘               ▼ (-) ──▶ e ──▶ ( )² ──▶ Loss
                              y ──┘
```
- **节点（Nodes）**：代表张量（Tensors，包括输入 $x$、权重 $w$、中间变量 $z$、输出 Loss）。
- **边/操作符（Edges / Operators）**：代表数学运算（`Mul`、`Add`、`Sub`、`Pow`、`ReLU` 等）。

---

### 2. 自动微分机制（Reverse-Mode Autodiff）

- **前向过程（Forward）**：
  - 计算各节点的输出值。
  - **保存反向传播所需的中间激活值（Save for backward）**，例如 ReLU 需要保存输入符号、Sigmoid 需要保存输出值、乘法需要保存对方的操作数。
- **反向过程（Backward）**：
  - 从标量 Loss 节点出发，初始梯度 $\frac{\partial L}{\partial L} = 1$。
  - 每个算子内部实现两个方法：`forward(ctx, x, y)` 和 `backward(ctx, grad_output)`。
  - 沿着拓扑逆序，将上游传来的 `grad_output` 乘以当前算子的局部偏导，传递给下游输入。

## 最小验证代码（PyTorch 动态图跟踪）

```python
import torch

# 1. 定义叶子节点张量 (Leaf Tensors)，开启梯度追踪
x = torch.tensor([2.0], requires_grad=False)
w = torch.tensor([3.0], requires_grad=True)
b = torch.tensor([1.0], requires_grad=True)
y_true = torch.tensor([10.0])

# 2. 前向传播：动态构建计算图
z = w * x + b           # z = 3*2 + 1 = 7, grad_fn=<AddBackward0>
loss = (z - y_true)**2  # loss = (7 - 10)^2 = 9, grad_fn=<PowBackward0>

# 3. 检查计算图上的反向指针
print(f"Loss 节点的反向算子: {loss.grad_fn}")
print(f"z 节点的反向算子: {z.grad_fn}")

# 4. 反向传播：自动沿图回溯求导
loss.backward()

# 5. 查看叶子节点的偏导数
# dLoss/dw = 2*(z - y)*x = 2*(7 - 10)*2 = -12.0
# dLoss/db = 2*(z - y)*1 = 2*(7 - 10)*1 = -6.0
print(f"w 的梯度 dLoss/dw: {w.grad.item():.1f} | b 的梯度 dLoss/db: {b.grad.item():.1f}")
```

## 工程与业务映射

- **为什么模型训练显存远大于推理显存？**
  - **训练阶段**：计算图在前向传播时必须在显存中**缓存所有层的中间激活张量（Activation Memory）**，直到反向传播消费完之后才能释放；
  - **推理阶段（RKNN / 部署）**：使用 `with torch.no_grad():` 或导出为 ONNX 时，**彻底关闭计算图构建**，每个算子算完立即释放输入显存，显存占用骤降 70% 以上。
- **张量分离（`.detach()`）与禁止求导（`requires_grad=False`）**：
  - 在 GAN 对抗训练、强化学习目标网络、或固定 Backbone 仅训练 Head 时，通过 `detach()` 可以切断计算图的分支，阻止梯度继续向前回传。

## 思考与自测

- **自测 1**：在 PyTorch 训练循环中，为什么每次 `loss.backward()` 之前必须执行 `optimizer.zero_grad()`？
  > *解析*：PyTorch 设计为**梯度默认累加（Gradient Accumulation）**而非覆盖。如果不手动清零，当前 Batch 计算出的梯度会直接累加到上一个 Batch 的梯度上，导致更新方向完全混乱。在显存不足时，这反而是实现大 Batch 训练的有效技巧（多次 backward 再一次 step）。

- **自测 2**：动态图（PyTorch / Eager 模式）与静态图（TensorFlow 1.x / ONNX）的核心优缺点是什么？
  > *解析*：动态图“即写即运行”，便于 Python 原生 Debug（可以直接断点调试打印 Tensor），灵活性极高；静态图先声明完整计算图再统一编译优化，易于算子融合（Operator Fusion）和嵌入式端侧（如 NPU/RKNN）硬件部署加速。

## 关联知识
- [[前向传播]]：在计算图上沿拓扑顺序由输入到输出正向运算。
- [[反向传播]]：在计算图上沿逆序自动执行链式法则求导。
- [[神经元模型]]：计算图中的基本乘加节点单元。
- [[梯度下降]]：获取计算图回传的梯度后执行参数更新。
